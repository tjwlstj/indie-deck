# 게임 폴더 발견과 하위 탐색

> 상태: **CURRENT — v0.1.4 소스 구현·로컬 검증 완료**
>
> 작성: 2026-10-05. 공개 v0.1.3의 기능 완료 기록과 혼동하지 않는다.
> 아래는 이번 소스 변경의 동작과 안전 경계다. 배포 자산은
> [v0.1.4 릴리즈](https://github.com/tjwlstj/indie-deck/releases/tag/v0.1.4)에서
> 별도로 확인한다. 실제 게임 실행·번역 성공과 public-feed 업데이트 설치는
> 아래 오프라인/읽기 전용 검증만으로 확인됐다고 주장하지 않는다.

## 사용자가 알아둘 점

게임 목록은 등록 폴더의 실제 파일을 확인해 만든다. 게임 이름을 하드코딩한
목록도, AI가 게임 여부를 추측한 목록도 아니다. 등록한 위치가 `D:\`처럼 넓을
수록 충분한 하위 탐색 깊이와 불필요한 내부 폴더 제외가 함께 필요하다.

예를 들어 `D:\게임모음\분류\게임명\Release\Game.exe`는 `D:\` 기준
4단계 아래에 있지만, `게임명`을 직접 등록하면 1단계 아래에 있다. 이전
설정의 깊이 2에서는 전자만 누락될 수 있다. 또 드라이브 루트가 이미 끝의
구분자를 포함한다는 점을 고려하지 않은 경로 경계 검사도 별도로 바로잡는다.

이번 변경 후 사용할 흐름은 다음과 같다.

1. **설정 → 라이브러리**에서 게임이 들어 있는 폴더를 등록한다.
2. **하위 폴더 탐색 깊이**를 확인한다. 새 설정의 기본값은 6, 최대는 12다.
   기존에 저장한 2를 자동으로 바꾸지는 않으므로 넓은 드라이브를 등록한
   사용자는 6으로 올리고 저장하는 것을 권한다.
3. **전체 다시 검색**을 실행한다. 깊이 저장만으로 즉시 재검색하지 않는다.
4. 확인한 폴더 수·게임 후보/발견 수 등 실제 집계와 현재 탐색 경로를 본다.
   전체 폴더 수를 미리 알 수 없으므로 임의의 완료 퍼센트를 표시하지 않는다.
5. 깊이 제한 안내가 남으면 필요한 범위 안에서 깊이를 늘리거나, 실제 게임
   모음 폴더를 추가 등록한다. 드라이브 전체보다 좁은 등록 위치가 효율적이다.

## 발견과 엔진 분류를 분리한다

탐색은 먼저 가벼운 디렉터리 목록에서 실행 후보를 찾고, 그 폴더의 구조를
알려진 엔진 서명과 대조한다. 엔진 분류는 번역기·로더·폰트 추천의 입력이다.
단순히 EXE가 있거나 엔진 관련 파일 하나가 있다는 이유만으로 게임을
확정하지 않는다.

- 실행 가능한 게임 후보와 알려진 엔진의 충분한 구조 근거가 함께 있어야
  자동 등록한다. 엔진 점수는 규칙 기반 휴리스틱이지 게임 실행 성공 확률이 아니다.
- 엔진 표식만 있는 상위 폴더에서는 탐색을 멈추지 않는다. 그 아래
  `Release`, `Build`, `Windows` 등에 실제 게임이 있을 수 있기 때문이다.
- 실제 게임을 찾은 뒤에는 해당 게임의 엔진 데이터·의존성·번역기·캐시
  내부를 다시 별도 게임으로 찾으러 내려가지 않도록 가지치기한다.
- 실행파일 이름이 같은 다른 설치 폴더를 이름만으로 합치지 않는다.
  겹쳐 등록한 루트에서 같은 실제 경로를 발견한 경우에는 중복을 제거한다.
- 미지원 엔진, 엔진 근거 없는 EXE만의 자동 게임 등록은 **이번 변경에 포함하지 않는다**.
  엔진 SDK·에디터·도구도 같은 엔진 표식을 가질 수 있어 모든 오탐을 없앤다는
  보장은 하지 않는다. 기존 엔진별 상세 필터도 유지한다.

탐색은 게임 파일을 실행·삭제·재설치하지 않는다. `.lnk`나 `.bat`를 자동
실행하는 경로도 추가하지 않는다. 번역기 설치와 게임 실행은 사용자가
선택하는 별도 작업이다.

## 하위 필터와 안전한 탐색 경계

`Windows`라는 폴더 이름 전체를 제외하면 정상 게임의 Windows 배포판도
사라진다. 따라서 시스템 제외는 실제 OS 경로의 경계로 판단한다. 예를 들어
실제 Windows 시스템 디렉터리는 피하지만 `D:\게임명\Windows`는 탐색할 수
있어야 한다. `Program Files`나 `Users` 역시 이름만으로 전체 하위를 버리지 않는다.

일반적인 게임 내부 데이터와 개발·의존성·도구 폴더는 보수적으로 제외한다.
실제 배포 위치일 수 있는 `Release`, `Build`, `Windows`를 일반 금지 이름으로
사용하지 않는다. 심볼릭 링크·junction을 따라 다른 위치로 탐색 범위를
넓히지 않으며, 읽기 권한이 없는 분기는 건너뛰고 안내한다.

넓은 드라이브 탐색에는 다음 제한을 둔다.

- 탐색 깊이 최대 12, 외부 탐색기에서 방문하는 폴더 최대 20,000개.
- 실행 후보의 엔진 점수 계산에는 엔진 하나당 새 디렉터리 목록 최대 128개를
  적용한다. 재귀 파일 검색뿐 아니라 여러 가지를 여는 디렉터리 glob도 같은
  예산을 쓴다. 예산이 부족한 엔진은 부분 점수로 확정하지 않고 그 판정을
  제외한다. 상위 폴더를 게임으로 오인해 하위 게임을 놓치지 않도록 탐색은
  계속하며, 엔진 판정 한도 집계를 안내한다.
- 탐색 중 주기적으로 실행을 양보해 화면과 취소 요청을 처리한다.
- 사용자가 취소하거나 방문 한도를 초과하면 부분 결과로 기존 저장 목록을
  덮어쓰지 않는다. 완료하지 않은 탐색을 성공한 전체 검색처럼 표시하지 않는다.
- 접근하지 못한 분기에 속한 기존 게임 항목은 보존한다. 권한 오류나
  등록 루트 자체의 일시적인 누락·드라이브 연결 해제를 게임 삭제의 증거로
  사용하지 않는다. 접근 가능한 등록 루트 안에서 실제로 사라진 하위 게임과는
  구분한다.
- 선택한 깊이에서 더 내려갈 폴더가 남았으면 깊이 제한 안내를 표시한다.
  정상 종료했다고 드라이브 모든 위치를 확인했다는 뜻은 아니다.

20,000은 외부 탐색기의 방문 수이며 128은 엔진별 새 디렉터리 목록 예산이다.
둘을 더한 값이 전체 OS 읽기 호출의 hard cap이라는 뜻은 아니다. 목록 캐시,
파일 존재 확인·메타데이터·작은 파일 읽기는 서로 다른 작업이며, 큰 디렉터리
하나에 들어 있는 파일 개수에도 실행 시간이 영향을 받는다.

취소·탐색 실패로 저장 전 중단된 경우에는 이전 목록을 유지했다고 표시한다.
반면 목록 저장은 끝났지만 후속 표시 정보·감사 결과를 만들지 못했다면
**목록 저장됨 — 표시 갱신 실패**로 구분한다. 이때 이전 목록이 보존됐다고
잘못 안내하지 않으며, 런처를 다시 읽어 저장된 목록을 확인하도록 한다.

폴더 이름과 파일 목록을 먼저 검사하고 필요한 작은 엔진 표식만 읽는다.
일반 검색에서 모든 게임 파일의 해시·크기 합계를 계산하거나 실행파일을
실행하는 것은 아니다. 큰 컬렉션의 실제 속도는 폴더 수·디스크 종류·백신·권한에
따라 달라지므로 다른 런처보다 빠르다는 성능 수치는 주장하지 않는다.

## 로컬 검증과 배포 경계

한국어·영어의 오프라인 Electron 흐름에서 설정 깊이 저장, 실제 탐색 진행,
화면 새로고침 뒤 상태·취소 버튼 복구, 취소 시 기존 목록 revision 유지와
그 뒤 정상 전체 검색 저장을 확인했다. 일회용 게임 폴더와 테스트 전용 지연을
사용하며, 일반 사용자 게임을 실행하거나 변경하는 검사는 아니다.

등록 루트 접근 실패와 엔진 내부 탐색 예산도 비변경 가상 파일시스템 진단으로
독립 확인했다. 등록 루트에 `ENOENT`를 주었을 때 기존 게임 행이 그대로
보존됐고, 넓은 후보 폴더의 엔진 판정은 예산 안내를 남기며 부분 점수로
게임을 등록하지 않았다. 실제 디스크 속도를 측정한 벤치마크는 아니다.
전체 자동 검사·패키징·main 반영·공개 릴리즈 완료 여부는 이 오프라인 화면
흐름과 구분한다. 실제 게임의 실행·번역 성공은 이 검증만으로 증명하지 않는다.

## 로컬 확인 기록

전체 자동 검사는 340개 중 339개 통과, 실패 0개, Windows 파일 링크 생성
권한 제한에 따른 skip 1개였다. 별도로 한국어·영어 Electron에서 깊이 저장,
실제 탐색 진행, renderer reload 후 취소, 기존 revision 유지와 재검색 완료를
확인했다. Unity 폰트·MTool·번역기 유지보수·ZIP 가져오기 회귀 흐름도 통과했다.

2026-10-05에 현재 등록 루트들을 읽기 전용으로 검사했다. 아래는 엔진 구조가
일치한 **후보 프로필 수**이며, 모든 항목이 실제 게임인지 실행해 확인한 숫자가
아니다. 개인 게임 이름이나 경로는 기록하지 않았다.

| 탐색 깊이 | 후보 프로필 | 외부 walker 방문 폴더 | 엔진 검사 한도에 닿은 후보 |
| --- | ---: | ---: | ---: |
| 2 | 119 | 380 | 6 |
| 4 | 156 | 1,936 | 7 |
| 6 | 160 | 8,925 | 7 |

6단계는 같은 신규 알고리즘의 2단계보다 41개 프로필을 더 찾았다. 각 검사는
약 5.9–9.3초였지만 연속 검사 중 OS 캐시 상태가 달라졌으므로 속도 개선률이나
깊이별 공정한 성능 비교로 사용하지 않는다. 사용자 설정과 저장 라이브러리는
검사 전후 SHA-256이 같았고 게임 실행·설치·파일 변경은 하지 않았다.

독립 가상 파일시스템 검사는 사라진 등록 루트의 기존 항목 보존과, 넓은 후보의
엔진 검사 한도를 재현했다. 후자의 목록 읽기는 기존 3,102회에서 146회로 줄었지만
이 수치 역시 실제 디스크 속도나 전체 읽기 한도 128을 의미하지 않는다.

## 이번 범위 밖

Steam/Epic/GOG 등의 manifest를 직접 가져오는 스토어 연동은 **PLANNED**이며
이번 변경에서는 구현하지 않는다. 계정 로그인·소유권 확인·스토어 설치나
업데이트도 하지 않는다. 연구한 소스의 방식이 즉시 이 기능의 구현 증거가
되는 것은 아니다.

파일 변경 감시를 통한 자동 증분 탐색, 게임 파일 전체 해시 캐시, 미지원 엔진의
확인 가능한 수동 후보 화면도 별도 후속 작업이다. 현재 엔진 구조 검사는
게임이 실제로 실행되는지, 번역기가 그 게임에서 정상 작동하는지 또는 게임
내용이 안전한지를 보증하지 않는다.
